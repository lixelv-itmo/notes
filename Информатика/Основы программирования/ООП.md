## Определение
**Объектно-ориентированное программирование (ООП)** — это методология программирования, основанная на представлении программы в виде совокупности **объектов**, каждый из которых является экземпляром определённого **класса**, а классы образуют иерархию наследования.

Основные цели ООП:
1.  Упрощение структуры кода.
2.  Повышение гибкости и надежности.
3.  Моделирование сущностей реального мира.

---
## Основные понятия

### Класс и Объект
*   **Класс** — это шаблон, чертёж или описание того, как объект должен выглядеть и вести себя. Он описывает состояние (поля) и поведение (методы).
*   **Объект** — это конкретный экземпляр класса, созданный в памяти.

*Аналогия*: Класс — это чертёж дома, Объект — это конкретный построенный дом.

```cpp
class Car { // Class
public:
    string model;
    void drive() { cout << "Driving"; }
};

int main() {
    Car myCar; // Object
    myCar.model = "Toyota";
}
```

## Основные принципы ООП

### 1. Инкапсуляция (Encapsulation)
Скрытие внутренней реализации и объединение данных и методов, работающих с ними, в один компонент. Доступ к данным осуществляется через публичные методы (геттеры/сеттеры).

**Зачем нужно:** Защита данных от некорректного изменения и уменьшение связности кода.

```cpp
class BankAccount {
private:
    double balance;

public:
    BankAccount(double initial) : balance(initial) {}

    void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }
    
    double getBalance() const { return balance; }
};
```

### 2. Наследование (Inheritance)
Механизм, позволяющий создавать новые классы на основе существующих (родительских). Новый класс перенимает свойства и методы родителя, добавляя свои собственные.

**Зачем нужно:** Повторное использование кода и создание иерархий.

```cpp
class Animal {
public:
    void eat() { std::cout << "I can eat!" << std::endl; }
};

class Dog : public Animal { // Dog inherits all from Animal
public:
    void bark() { std::cout << "Woof!" << std::endl; }
};

// Dog dog;
// dog.eat();
// dog.bark();
```

### 3. Полиморфизм (Polymorphism)
Способность объектов с одинаковой спецификацией иметь различную реализацию. Позволяет использовать один и тот же интерфейс для разного действия объектов. Чаще всего реализуется через `virtual` функции.

**Зачем нужно:** Гибкость кода, работа с группой разных объектов через единый тип данных.

```cpp
class Animal {
public:
    virtual void makeSound() { std::cout << "Some sound" << std::endl; }
    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    void makeSound() override { std::cout << "Bark" << std::endl; }
};

class Cat : public Animal {
public:
    void makeSound() override { std::cout << "Meow" << std::endl; }
};

int main() {
    Animal* a1 = new Dog();
    Animal* a2 = new Cat();
    
    a1->makeSound(); // Выведет: Bark
    a2->makeSound(); // Выведет: Meow
}
```

### 4. Абстракция (Abstraction)
Выделение значимых характеристик объекта и игнорирование незначимых деталей. Реализуется через абстрактные классы (содержат чисто виртуальные функции) и интерфейсы.

**Зачем нужно:** Уменьшение сложности системы. Мы работаем с моделью, а не с реальным сложным объектом.

```cpp
class IShape {
public:
    virtual double getArea() = 0;
};

class Circle : public IShape {
    double r;
public:
    Circle(double r) : r(r) {}
    double getArea() override { return 3.14 * r * r; }
};
```

## Принципы SOLID
Хорошее ООП строится не только на 4 столпах, но и на принципах SOLID:
*   **S** (Single Responsibility) — принцип единственной ответственности.
*   **O** (Open-Closed) — принцип открытости/закрытости.
*   **L** (Liskov Substitution) — принцип подстановки Барбары Лисков.
*   **I** (Interface Segregation) — принцип разделения интерфейса.
*   **D** (Dependency Inversion) — принцип инверсии зависимостей.

## Преимущества и недостатки

| Преимущества | Недостатки |
| :--- | :--- |
| **Модульность:** Код разбит на логические блоки. | **Размер:** Программы обычно занимают больше памяти. |
| **Безопасность:** Данные защищены инкапсуляцией. | **Производительность:** Накладные расходы (виртуальные таблицы, вызовы). |
| **Поддержка:** Легче искать ошибки и обновлять код. | **Сложность:** Требует изменения образа мышления и проектирования. |
| **Переиспользование:** Наследование сокращает дублирование. | |
